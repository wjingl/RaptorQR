# 发送端文件传出管理系统 — 实现方案（v4：含完整安全设计）

## 一、目标与范围
新文件夹 **`send_manager/`** 内实现完整服务端系统（不触碰现有任何文件）：
- 适配 **Linux x86 服务器**（glibc 主流发行版），内网部署，默认端口 **1145**，IP:端口 访问
- 账号：自助注册 + 总管理审批；批量注册（统一初始密码+首次强制改密）；总管理可重置密码/停用/归档
- 普通用户仅见自己传出记录；总管理可看全部记录、全局统计与每人统计
- 发送工作台：复用现有 RaptorQR 彩色版发送页（零改动注入桥接层），选择目的地 **jzw/bgw/my/sjw** 后发送并自动生成记录
- 接收端：纯本地 HTML，提供"真实版"与"发布版（防逆向尽力而为）"
- 全流程测试 + 一键部署与维护自动化

## 二、技术选型（已联网调研验证，全部成熟开源组件）
| 领域 | 组件 | 理由 |
|---|---|---|
| 运行时 | **Node.js 24 LTS**（Active LTS，EOL 2028-04） | Node 20 已 EOL；better-sqlite3 v13 需 Node 22+；捆绑部署 ABI 一致 |
| Web 框架 | **Express 5** | 当前主流，异步错误自动处理 |
| 数据库 | **better-sqlite3 v13** | N-API 预编译随包发布、离线零编译、WAL、db.backup() |
| 会话 | **express-session + express-session-better-sqlite3** | 活跃 MIT 替代停维护旧包，服务端会话可撤销 |
| 密码 | **bcryptjs v3** | 纯 JS、零原生依赖、单向哈希 |
| 安全头 | **helmet**；**csrf**（pillarjs） | 响应头 + CSRF 双提交令牌 |
| 限流/锁定 | **express-rate-limit** | 登录按 IP+用户名 限流（主防御） |
| 验证码 | **@depup/svg-captcha**（维护 fork） | 辅助层，答案只存哈希+过期 |
| 校验 | **joi**；日志 **morgan + rotating-file-stream**；测试 **node:test + supertest** | 成熟组件 |

前端纯静态 JS（零构建链，暗色 #0d1117、系统字体、手机自适应）。部署可靠性：全部依赖纯 JS + better-sqlite3 N-API 预编译 → 服务器无环境/无网络/无编译器可跑；部署包含全量 node_modules + 捆绑 Node 24。

## 四、数据库模型（SQLite, WAL）
users(id, username UNIQUE, display_name, pass_hash, role[admin/user], status[pending/active/disabled/archived], must_change_password, created_at/by, approved_by/at, reject_reason, last_login_at)
records(id, user_id, username, filename, size, mime, is_text, destination[jzw/bgw/my/sjw], status[sending/completed/stopped/failed], sha256, started_at, completed_at, note)
audit(id, ts, user_id, username, action, detail, ip)；sessions 表由 store 管理；索引覆盖查询路径；全参数化查询。

## 五、API
认证：POST /api/auth/login·logout·register·change-password·change-password-forced；GET /api/auth/session、/api/captcha
用户（总管理）：GET /api/users、approve/reject、POST /api/users/batch、reset-password、status、role
记录：POST /api/records、POST /api/records/:id/status、GET /api/records（本人仅自己；总管理全部+筛选）
统计：GET /api/stats/overview·users·destinations·daily；审计：GET /api/audit（总管理）；系统：GET /api/health（公开）、/api/system/info（总管理）
权限全在服务端校验；普通用户前端不加载管理代码；响应永不含 pass_hash/token/captcha 明文。

## 六、发送工作台（零改动复用现有核心业务）
`/app` 服务时 `bridge.js` 在 `</body>` 前注入独立 `<script>`（源文件字节不变）。桥接工具栏（暗色 UI）：目的地下拉 **jzw/bgw/my/sjw**（必选）→ 选择文件（触发应用隐藏 input，读 name/size/mime+SHA-256）→ 开始发送（点击应用 Start Live QR）→ 标记完成。记录联动：开始→POST /api/records(sending)；MutationObserver 监听状态行自动更新运行/停止；完成→completed；绕过桥接提示未记录；文本模式支持。

## 七、接收端 真实版/发布版
`build_receiver.js` 复用 build_color.js 切分逻辑。真实版 real.html：完整应用+初始 hash=receiver 直接进入接收界面，代码可读。发布版 release.html：仅保留 decode worker+3 个必需 wasm；入口直接渲染接收端；codec 尽力混淆（base64+XOR 字节编码+紧凑 loader，不做标识符重命名避免破坏）；README 如实声明可被逆向、属尽力而为。两版纯本地离线可用，`/receiver` 提供下载页。

## 八、安全设计（纵深防御）
**威胁模型**：外部可触达 1145 端口、内网恶意人员、被控客户端三类攻击者；防破坏/防窃取/防滥用。

### 8.1 账户安全
- bcryptjs(cost 12) 单向哈希；密码长度 8–64（bcrypt 72 字节上限防 CPU DoS）；timingSafeEqual 比对
- 登录限流：express-rate-limit 按 IP+用户名 双键，5 次失败/15 分钟锁定 15 分钟；失败 2 次后强制验证码
- 验证码：SVG 数学题，答案 sha256+salt 存储、5 分钟过期、一次性；每次登录轮换会话防固定；登出/改密/停用即销毁服务端会话；改密后强制重登
- 会话：256-bit 随机 token，库中只存 sha256；HttpOnly+SameSite=Strict+Path=/；绝对 12h/空闲 30min 双过期；会话密钥首启生成入 secrets 文件(chmod 600)
- 注册：用户名白名单字符/长度限制/禁用保留名(admin/setup/root 等)；注册限流防批量轰炸；未审批不能登录
- 停用账号每次请求实时校验；首登/重置后 mustChangePassword 强制改密；所有敏感操作审计

### 8.2 应用层（Web）安全
- helmet：nosniff、X-Frame-Options(管理页 DENY/应用页 SAMEORIGIN)、no-referrer、frame-ancestors 'none'、COOP/CORP
- CSP 分级：管理页严格 `default-src 'self'`；仅 /app 页放行 data:/blob:（worker/wasm 必需）
- CSRF：SameSite=Strict + X-CSRF-Token 双提交 + Origin 校验，全部写接口强制
- XSS：服务端转义渲染 + 禁止 innerHTML 拼用户数据；管理页禁内联脚本
- SQL 注入：全参数化查询，禁止字符串拼接 SQL；joi 全端点 schema
- 请求上限：JSON body 100KB、批量导入 1MB、URL/参数长度上限；目的地白名单枚举
- 路径穿越：静态服务固定目录 + dotfiles ignore + 路由白名单；无用户可控文件路径
- **零上传/执行面**：记录仅元数据，不做文件上传/存储/执行；无出站网络（无 SSRF）；无子进程/shell 执行

### 8.3 内存与资源安全（防 DoS）
- server.requestTimeout/headersTimeout/keepAliveTimeout + maxConnections + 请求体大小上限
- 全列表接口分页（默认 50/最大 100）；统计用 SQL 聚合 + 时间窗口，不整表载入
- bcrypt/captcha 输入长度上限；限流兜底；单进程同步 SQLite 天然串行 + WAL + busy_timeout；会话表 TTL 清理；静态资源流式传输

### 8.4 数据库管理安全
- 专用服务账号 + 数据/日志目录 chmod 600/640、umask 077；DB 不在 Web 根目录
- 版本化迁移表（启动事务内执行）；敏感字段不落明文（密码/会话/captcha 全哈希）
- WAL+定期 checkpoint；备份走 better-sqlite3 backup API 到独立目录(600)+保留 7 份+完整性校验
- 备份/导出仅服务器本地执行；cli.js 仅限服务器本机服务账号运行（OS 级信任边界，文档明示）

### 8.5 基础设施与运维
- 部署：专用非 root 用户 + systemd 加固（NoNewPrivileges、ProtectSystem=strict、PrivateTmp、ReadOnlyPaths=代码、WritablePaths=data/logs）；nohup 仅兜底
- 错误处理：统一错误中间件，生产不泄漏堆栈；访问/审计日志分离、不含敏感字段、按天轮转、权限 600
- 动态页 no-cache；静态资源指纹缓存；HTTPS：默认内网 HTTP，config 预留 TLS（Node https 或反代）说明；README 强调防火墙仅放行办公网段 1145
- 依赖安全：package-lock 精确锁定 + 构建机 npm audit + 选型均为活跃维护组件；优雅停机（SIGTERM→关 server→checkpoint→关库）；update.sh 支持回滚

## 九、部署与维护
